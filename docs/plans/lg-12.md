# LG-12 — Conclude a league season

**Status:** approved 2026-08-09 (clarify gate answered by owner)
**Ref:** spec §End of League, §Game Mode 1 Core Rules; arch D10; ADR-0025, ADR-0027; new ADR-0030.

## Problem

`LEAGUE_STATUS.CONCLUDED` is read in six places and written by nothing:

| Reader | What it does with `concluded` |
| --- | --- |
| `pickem/picks.ts`, `survivor/picks.ts` | refuse a pick on a finished season |
| `leagues/join.ts`, `invites.ts` | refuse a join / explain the block |
| `discovery.ts` | hide the league from browse |
| `leagues/authz.ts` | drop it from the 10-active-commissioner cap |
| `settlement.ts::settleSweep` | **skip it in the nightly recompute** |

So today: the refusal is unreachable in every mode, and every league season ever
created is recomputed by `settle-sweep` every night forever — Survivor's replay
being whole-season, that cost grows with seasons × weeks. Separately,
`survivor/season.ts::rangePlayedOut` re-derives "has this season finished" from
raw game statuses because nothing stores the answer, duplicating the week loop
in `survivor/settlement.ts` with only a pair of comments holding them together.

## Decision (ADR-0030)

**`league_seasons.status` becomes settlement's output — a materialized
derivation, not independent state.** It joins `pickem_standings`,
`survivor_state` and the rest of arch D10's recomputable set.

```
concluded  ⇔  superseded  ∨  mode-decided
```

- **superseded** — an instance of the same league is bound to a strictly greater
  `sport_seasons.year`. Mode-agnostic; this is renewal's half.
- **mode-decided** —
  - *Pick'em*: every in-range week of the bound season holds games, and every one
    of those games is terminal (`final` with both scores, or `cancelled`).
    Independent of picks, so a league nobody played still ends.
  - *Survivor*: ADR-0027's two arms, taken straight from the replay — it graded
    every in-range week without breaking, or it broke on the sole-survivor
    reduction.

**Both directions are written.** A rebuild that finds the season no longer
finished writes `active` back. This is what keeps arch D10 literally true: an
admin override that un-finals a game reopens the season, re-applying it
re-concludes, and no state survives that a full recompute wouldn't reproduce.

**Three writers, one function.** `applyLeagueSeasonConclusion` in
`services/leagues/conclusion.ts`; the two mode settlements call it inside their
settling transaction with their mode answer, renewal calls it with `false` on the
instance it just superseded (the superseded arm then fires on the row renewal
inserted moments earlier in the same transaction).

  now reachable through a real settled season rather than a hand-set status.

## Concurrency

Renewal takes `lockLeagueSeasonRow` on the instance it closes — settlement's own
lock — before writing. Without it, a rebuild of the prior instance in flight
during the renewal computes `superseded` against a snapshot predating the INSERT
and writes `active` back over it. No lock-ordering risk: settlement acquires only
the league-season lock, so nothing takes these two in the opposite order.
