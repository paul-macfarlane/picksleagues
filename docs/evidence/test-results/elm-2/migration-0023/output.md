# ELM-2 — migration 0023, and the constraint that carries the mode's rule

`packages/db/migrations/0023_dark_nova.sql`, generated by
`pnpm --filter @picksleagues/db generate` (drizzle-kit). The generated filename
was kept as-is and `meta/_journal.json` was written by the tool, never by hand.

Applied cleanly to a fresh database by the integration suite's global setup on
every run of `pnpm test:integration` (see `suites/output.md`).

## The team ledger

```sql
CREATE UNIQUE INDEX "survivor_picks_member_team_unique"
  ON "survivor_picks" USING btree ("league_season_id","league_member_id","team_id")
  WHERE not "survivor_picks"."released";
```

The `WHERE` clause is the whole point, and it is why the test asserts on the
index *definition* rather than on the index name. Spec §Game Mode 2 says a
member may pick each NFL team at most once per league — but it also says a
**cancelled** game's pick pushes and the team is **not** consumed. A plain
unique index under this same name would satisfy the first rule and silently
break the second, refusing a re-pick the spec explicitly permits. Nothing else
in ELM-2 could catch that, because the release path itself is settlement's and
lands with ELM-4.

`released` is written only by settlement. ADR-0025 records the design, including
the sticky-release rule that keeps a reverted cancellation from making a
recompute collide with this index and leave a league-season unsettleable.

## The rest of the migration

```sql
CREATE TABLE "survivor_picks" (
	"id" uuid PRIMARY KEY DEFAULT gen_random_uuid() NOT NULL,
	"league_season_id" uuid NOT NULL,
	"league_member_id" uuid NOT NULL,
	"week_id" uuid NOT NULL,
	"game_id" uuid NOT NULL,
	"team_id" uuid NOT NULL,
	"spread_at_pick" double precision,
	"released" boolean DEFAULT false NOT NULL,
	"created_at" timestamp with time zone NOT NULL,
	"updated_at" timestamp with time zone NOT NULL,
	CONSTRAINT "survivor_picks_member_week_unique" UNIQUE("league_season_id","league_member_id","week_id")
);

CREATE TABLE "survivor_state" (
	"id" uuid PRIMARY KEY DEFAULT gen_random_uuid() NOT NULL,
	"league_season_id" uuid NOT NULL,
	"league_member_id" uuid NOT NULL,
	"lives_remaining" integer DEFAULT 1 NOT NULL,
	"eliminated_week_id" uuid,
	"revived_count" integer DEFAULT 0 NOT NULL,
	"updated_at" timestamp with time zone NOT NULL,
	CONSTRAINT "survivor_state_season_member_unique" UNIQUE("league_season_id","league_member_id")
);
```

Foreign keys: `league_season_id` and `league_member_id` cascade; `week_id`,
`game_id`, `team_id`, and `eliminated_week_id` restrict. `week_id` restricts for
the same reason `pickem_picks.week_id` does (ADR-0015's closing note) — a live
pick must be able to block deletion of its week, or the schedule sync's
convergence sweep would drop the week out from under it.

Neither table has a `locked` column (arch D11 — lock state is derived on every
read and re-validated in every write transaction) and neither timestamp carries
`.defaultNow()` (arch D13 — every "now" comes from the injected Clock, so the
simulator moves these with everything else).

Supporting indexes: `(league_season_id, week_id)`, `(league_member_id, week_id)`,
`(game_id)`.
