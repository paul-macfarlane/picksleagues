# Epic: Scope Sweep (SWP)

Complexity-vs-value sweep the owner asked for (2026-08-09): the app serves
friends and co-workers, <50 users — every feature is judged against whether a
real league of people who know each other will use it, not against internet
scale. Candidates cover shipped surfaces and slated work alike. Epic 12 (SIMP)
was the same exercise scoped to Pick'em rules; this one is app-wide.

Every item entered as a **question before it is a change**, tagged
`needs-triage` until the owner ruled. The owner ruled 2026-08-09: SWP-1, 2, 4,
5, 6 accepted as cuts and SWP-7 as a shrink — those are now runnable work; only
SWP-3 remains open. An accepted cut that touches the locked docs ships as ADR +
spec amendment plus the deletion, per the SIMP precedent.

- [ ] **SWP-1** — Cut Pick'em playoff support: the Postseason and Full Season presets collapse to Regular Season only, matching Survivor (ADR-0024's shape). Inherits scrapped FB-7's framing: the support is week-ordering plus short-slate handling that already exists, so the question is what a real league would miss — and a friends' Pick'em league is a regular-season ritual that ends when the season does. Reopens ADR-0007 (playoffs in scope) and ADR-0020 (three presets); cutting needs a superseding ADR + spec amendment. Accepted: cut (owner, 2026-08-09). _(deps: none)_
- [ ] **SWP-2** — Scrap the Trust & Safety epic (TS-1–TS-5). Member reporting, in-app notifications, kick reasons, named commissioner invites, and avatar moderation all solve stranger-scale problems; among people who know each other, disputes resolve socially (the spec already says so for mid-season conflicts) and the admin remedy for a bad avatar is the direct database update TS-5 itself names. Cutting slated work touches no code and no locked doc — the epic gets `wontfix` lines and the build order drops step 6. Accepted: cut (owner, 2026-08-09). _(deps: none)_
- [ ] **SWP-3** — Decide whether public visibility + discovery stays. It is shipped and cheap to keep (a route, a setting, a browse query), but it is the sole surface exposing the app to strangers — the only reason epic 10 exists. If no real league will ever be public, cutting deletes the discovery page, the visibility setting, and the entire abuse surface in one move; if the owner wants "share the app with the office" to stay one click, keep it and let SWP-2 stand on its own. Recommendation: owner's call — keep costs little, but keeping it while scrapping TS means accepting that a public league has no in-app recourse. _(deps: none)_ _(needs-triage)_
- [ ] **SWP-4** — Cut invite-link expiry and max-use caps; a link becomes a bare opaque code, revocable anytime (ADR-0029 already covers the leak case). Nobody handing a link to friends sets an expiry or a use cap — the options are two form fields, two columns, and enforcement logic for a knob the audience won't turn. Spec §Invites amendment. Accepted: cut (owner, 2026-08-09). _(deps: none)_
- [ ] **SWP-5** — Fix Survivor's Push/Tie Resolution at its default (advance, team consumed) and remove the setting — the same reasoning that removed Survivor's Pick Type (ADR-0026) and season range (ADR-0024): NFL ties run one or two a season, and a setting nobody changes is a control offering one option. Spec §Game Mode 2 amendment. Accepted: cut (owner, 2026-08-09). _(deps: none)_
- [ ] **SWP-6** — Trim March Madness before it is built (epic 07 is unstarted, so this is the cheapest place to save): drop the Custom scoring model (standard doubling only — a friends' pool doesn't tune per-round values), and drop the pre-deadline seed-correction wipe-and-resubmit flow (an admin handles the once-a-tournament case by hand at this scale). Vacated-slot auto-advance stays — it is grading correctness, not a feature. MM-3/MM-4/MM-6/MM-8 shrink accordingly. Accepted: cut both named sub-features (owner, 2026-08-09). _(deps: none)_
- [ ] **SWP-7** — Shrink FB-2's perf-audit bound from "dozens to low hundreds of leagues" to the real one: a handful of leagues settling in the same window. At that bound the audit collapses to one timing of a full `settle-sweep` against a realistically sized dev dataset — fix only what that measurement shows, which is plausibly nothing. Accepted: shrink (owner, 2026-08-09) — the measurement is cheap and ends the question. _(deps: none)_
