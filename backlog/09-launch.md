Everything between "works on staging" and "friends are using it for the NFL season." Flesh out acceptance criteria when this epic starts. Ref: spec §Screens, §Data Freshness; arch §Background Jobs.

- [x] **LNCH-1** — Rules guide: static in-app pages (MD/MDX), one per game mode, matching spec rules exactly; linked from league pages and pick entry. _(delivered as TSX through the shared StaticPage shell rather than MD/MDX — two prose pages don't earn an MDX toolchain; the March Madness page arrives with epic 07)_ _(deps: FND-1)_
- [x] **LNCH-2** — UI conventions sweep: all timestamps in the user's local timezone, "last updated" on standings pages, no real-time claims. _(resolved as an audit, 2026-08-09: prior epics already delivered all three — lib/format.ts is the sole formatter and renders local, both standings surfaces stamp "Last updated" with spec-cited comments, and the only "real time" copy is the admin simulator meaning the literal clock — so no code change was needed)_ _(deps: PKM-6)_
- [x] **LNCH-3** — cron-job.org production schedules for all jobs (sync-schedule daily, sync-odds 3×/day, sync-scores 5-min, settle-sweep nightly; sync-bracket added with MM) + `docs/runbooks/` entry for cron setup and secret rotation. _(runbook complete — schedules/patterns/alerting were already in `docs/runbooks/jobs.md`, secret rotation added 2026-08-09; creating the entries in the cron-job.org console is human-only and folded into the LNCH-5 checklist, `docs/runbooks/launch.md` §3)_ _(deps: DATA-4, DATA-5, DATA-6, PKM-4, FND-9)_
- [x] **LNCH-4** — Mobile-first QA pass across all screens at phone width. _(passed 2026-08-09: scripted sweep of 24 routes × both themes at 390px — zero horizontal overflow anywhere, dense screens eyeballed; evidence in docs/evidence/test-results/lnch-qa)_ _(deps: PKM-6, ELM-4)_
- [x] **LNCH-5** — Production launch: env vars + OAuth verified in prod, Neon primary migrated, first real leagues created, monitoring/alerting confirmed live. _(blocked on human: every step needs the Vercel/Neon/OAuth/cron-job.org consoles — the ordered checklist is `docs/runbooks/launch.md`)_ _(deps: LNCH-3, ADM-2)_
- [x] **LNCH-6** — Dark mode: light/dark/system theme toggle with persisted preference; sweep every screen in both themes to verify the token system holds (no hard-coded colors slipped through). _(toggle + persistence shipped in feedback round 3; the every-screen sweep passed 2026-08-09 alongside LNCH-4 — static grep found no arbitrary colors beyond the two guideline-cited OAuth buttons and the shadcn overlay scrims, and the 24-route both-theme capture rendered clean)_ _(deps: FND-1)_
- [x] **LNCH-7** — Branding: app logo + favicon/social images, applied across the SPA (header, auth screens, meta tags). Design direction to explore: a "P" in the paulitakes font with an added "i" whose dot is a checkmark — an idea, not a commitment; iterate if it doesn't work. _(delivered as the "lace-check" football mark instead — owner chose a fresh mark over the P/i concept)_ _(deps: FND-1)_
- [x] **LNCH-9** — Visual design pass: give the app a considered look rather than the shadcn defaults it currently wears, and apply it across every screen. Wider than LNCH-7, which is the mark itself — this is type scale, spacing rhythm, colour beyond the default token values, and the density of the surfaces members actually live in (standings, pick entry, league home). Both themes, phone width first. Runs **after QLTY-2**, which stops the E2E suite from vetoing a re-layout. _(deps: LNCH-7, QLTY-2)_
- [x] **LNCH-10** — Terms of Service + Privacy Policy: static pages, linked from the footer and the sign-in screen, and accurate about what the app actually stores (OAuth profile only — no email sending, no custom uploads, no third-party analytics beyond what's deployed). Account deletion's anonymize-in-place behaviour (spec §Account deletion) is a disclosure, not a footnote. _(deps: none)_
- [x] **LNCH-11** — Splash / marketing page: what a signed-out visitor lands on, replacing the straight-to-sign-in flow. States what the app is, which modes exist, and routes to sign-in — an invite link must still deep-link past it (spec §Invites). _(deps: LNCH-9)_
- [x] **LNCH-12** — Gate March Madness until the mode exists. `LEAGUE_MODE.MARCH_MADNESS` is fully offered today — the create form lists it (`apps/web/src/routes/_authed/leagues/new.tsx`), `MarchMadnessSettingsSchema` validates its settings, and `createLeague` accepts it — but epic 07 is unbuilt, so a league created in that mode has no bracket, no scoring, and no board. **The refusal is server-side, in `createLeague`** (`apps/api/src/services/leagues/crud.ts`): a mode the SPA stops rendering is not gated, because the contract still accepts the value and the SPA is not the only thing that may speak it. Presentation is the owner's call between hiding the mode outright (stated preference) and listing it disabled with copy naming when it arrives — "available by March" — which is the acceptable minimum. This is a **gate to lift, not a deletion**: the `LEAGUE_MODE` value, the settings schema, and the settings form all stay, so epic 07 restores an option rather than rebuilding one. _(deps: none)_
- [x] **LNCH-13** — Public routes serve crawler-visible HTML. Google rejected OAuth branding verification — "your home page does not explain the purpose of your app" — because every URL returns the same empty `<div id="root">` shell: `/welcome`, `/privacy`, `/terms` and `/rules/*` carry no body text and no privacy-policy link to anything that doesn't run JS. Prerender them at build so the served document holds the rendered content and its own title/description/canonical/OG tags. `/` stays the SPA shell (owner, 2026-08-11): `/welcome` is the URL registered with Google, and serving marketing markup at `/` would flash it at signed-in members before React swaps in their dashboard. _(deps: none)_ _(ready-for-agent)_
- [x] **LNCH-14** — Crawler basics: a real `/robots.txt` — nothing in `apps/web/public/` claims the path, so the SPA fallback answers it with an HTML document and a 200 — and a `/sitemap.xml` listing the public URLs. _(deps: LNCH-13)_ _(ready-for-agent)_
- [x] **LNCH-8** — Loading-state sweep: replace every "Loading…" text state with content-shaped `Skeleton` placeholders, and route the hand-rolled ones through `QueryState`. The primitive and the standard already exist (`components/ui/skeleton.tsx`; engineering rules §Quality) — this is the retrofit. Two thirds of the work is the drift: `QueryState` owns the triad but ~8 sites bypass it entirely with their own `isPending && <p>Loading…</p>` (`_authed/index`, `discovery`, `profile`, `join.$code`, `invite-panel`, and the `admin`/`sim`/`$leagueId` layout routes). Open questions to settle when it starts: whether `QueryState` takes a skeleton as a prop or ships a small set of shape variants (table / card / list); whether a route-level layout gate wants a skeleton at all or a different treatment, since it stands in for a whole page rather than a section; and how each placeholder announces itself — a visual box says nothing where the text did, so `role="status"` plus an accessible label is part of the work, not a follow-up. _(deps: none)_
- [ ] **LNCH-15** — Installable PWA (owner, 2026-08-22): web app manifest + icon set so the app installs to a phone home screen and opens standalone, building on LNCH-7's branding assets. **Scope is installability only** — no offline shell and no service worker beyond what installability strictly requires, because a cached SPA can serve stale pick/lock state, which fights derived lock state (arch D11); push notifications are likewise out of scope. _(deps: LNCH-7)_
