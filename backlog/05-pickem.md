# Epic: NFL Pick'em (PKM)

The first game mode, plus the **shared settlement core** (`pick_results`, `standings`, settle orchestration, nightly sweep) that ELM and MM reuse. Ref: spec §Game Mode 1; arch §Settlement & Scoring, §Locking Model, D9–D11.

> **Playoffs (owner decision, ADR-0007, settled 2026-07-22):** pick'em leagues MAY extend into the playoffs — End Week can be a playoff round (Wild Card → Super Bowl; spec §Game Mode 1 updated). PKM-1's `PickemSettings` must model BOTH Start Week and End Week as (week type, week number) — playoffs-only leagues are allowed (e.g. Wild Card → Super Bowl); week ordering is season order (playoff rounds follow week 18). PKM-3's scoring needs no special casing — the existing fewer-games-than-Picks-Per-Week rule covers small playoff slates.

- [x] **PKM-9** — Credit the sportsbook behind the spread on the ATS surfaces that display one. **The book is data, not a constant:** ESPN names it per event at `competition.odds[0].provider` (DraftKings as of 2026-08-07; ESPN has rotated books before), so a string baked into a component becomes a false claim the first time that changes, silently and with nothing to catch it. Capture `provider.name` in the ESPN adapter's `ProviderGame`, add a nullable `games.spread_source`, and write it in the same `set()` as `spread` in `sync-odds` — a provider field, never an `override_*` (arch D15). It then freezes alongside the last-priced number, which is what keeps the credit correct on a submitted week whose game is long final: ESPN drops `odds` from the payload entirely once a game starts, so the source can only be captured while the game is still scheduled. Serialize onto `SlateGame` and the pick DTOs; regenerate and commit `openapi/`. **Render it only where the displayed number is actually that book's:** not when `override_spread` is set (a commissioner's correction is not the book's line), and not in SU leagues, which show no spread at all. **Amended during delivery:** this originally also excluded `SimulatedProvider`, on the grounds that synthesized spreads (SIM-6) carry no source — but that made the credit unreachable from the simulator, which is the harness that would have verified it. The simulator now reports production's attributed book on a priced fixture, accepting that it credits a real book for numbers it never priced; contained because the simulator is dev-only (ADR-0011). Plain text, no logo — ESPN ships light/dark brand SVGs in the same payload, and rendering one reads as a partnership we don't have. Placement: one line per pick card and on the week detail, near the existing "as of" copy, rather than per game row — the whole slate is priced from a single provider response, so a per-row credit is the same string sixteen times. **Credit the book, not ESPN:** a site-footer "Data from ESPN" line was considered and declined — `site.api.espn.com` is an undocumented endpoint with no attribution terms to satisfy, an ESPN wordmark reads as an affiliation we don't have, and the provenance question a member actually has is already answered by the "as of" and "last updated" stamps. The book is named because the line is the term they're graded against and they can't check it without knowing whose it is; a score carries no such obligation. _(deps: none)_ _(ready-for-agent)_
- [x] **PKM-10** — Pick'em pick-status glance on the dashboard. LG-7 is marked done and its line claims "my leagues with pick-status at a glance", but it shipped the card plus a `Pick status coming soon` placeholder; ELM-6 filled that placeholder for Survivor only, so the dashboard now states a real status for one mode and a promise for the other. **Pick'em's glance is a different shape** — a week is N picks committed as one immutable submission (ADR-0018), not one pick changeable until kickoff — so it needs its own state set beside `survivorPickStatus` on `LeagueSummary`, never a widened shared one (the mode-naming rule's test: name the second mode that would use it unchanged). The glance resolves server-side for the same reason Survivor's does: lock is derived from the injected Clock, and under the simulator the browser sits at a different instant. Ref: spec §Screens. **Delivered with a fourth state beyond the spec's three (owner decision during delivery): `season_complete`, read from the league season's stored ending (ADR-0030) and asked ahead of every week state — the current-week resolution falls back to the last week played, so without it a finished league would report that week forever.** The count of picks still owed is deliberately *not* on the wire: the pick screen states the exact required set one click away, and a dashboard copy of it could only ever be staler. The batched "which week is this league on, and is it still open" resolution is now shared with Survivor's glance (`resolveLeagueWeekFrames`), so the two modes cannot disagree about which week a member owes. _(deps: none)_
