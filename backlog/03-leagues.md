# Epic: Leagues (LG)

League lifecycle, membership, invites, discovery, and commissioner powers — the mode-agnostic core. Ref: spec §Leagues; arch §Invites, §Domain Model, §API Surface.

- [x] **LG-1** — Drizzle schema: `leagues` (mode, visibility, status), `league_settings` (JSONB validated by per-mode Zod schema, typed via `$type<>`), `league_members` (role carries commissionership — no `commissioner_id` on `leagues`, ADR-0004), `league_invites`. _(deps: FND-2)_
- [x] **LG-2** — League creation flow (mode → name → visibility → mode settings → pre-start league) with the 10-active-commissioner cap enforced in-transaction. _(deps: LG-1, ID-1)_
- [x] **LG-3** — Invites: generate/revoke links with opaque codes, optional expiry + max-use; `/join/:code` with signed-out → auth → back-to-join round-trip. _(deps: LG-2)_
- [x] **LG-4** — Membership rules at the join endpoint: 2–100 size, one membership per user, clock-derived join cutoff (first week started / Round of 64 tipped). _(deps: LG-3, DATA-4, FND-6)_
- [x] **LG-5** — Public discovery: browse page of public pre-cutoff leagues + name search (`GET /discovery`). _(deps: LG-2)_
- [x] **LG-6** — Commissioner powers with pre-start/post-start windows: settings + kick + delete pre-start only, cosmetics + promote/demote commissioners anytime (promote cap-checked; ≥1-commissioner invariant, ADR-0004). **Also inherited from ID-3:** wire the last-commissioner guard into account deletion — `deleteAccount` in `apps/api/src/services/users.ts` has a `TODO(LG-6, ADR-0004)` marking where the check runs inside the deletion transaction (block with 409 while the user is the last commissioner of any non-empty active league); shipped unguarded in ID-3 because it's vacuously safe with no league tables. _(deps: LG-2)_
- [x] **LG-7** — Dashboard (my leagues with pick-status at a glance) + league home shell (members, info, commissioner tools; standings slot filled per mode later). _(deps: LG-2)_
- [x] **LG-8** — Leave league, pre-start only per spec §Membership (ADR-0004): the last commissioner of a league with other members must promote a replacement first (same ≥1-commissioner guard as account deletion, ID-3); a commissioner who is the only member deletes the league instead. _(deps: LG-6)_
- [x] **LG-9** — The create form offers only the season-range presets the bound season can still start. Today a preset whose whole range has already run is accepted by the form and refused by the server with `start_week_passed` — a refusal a Pick'em commissioner cannot act on, since SIMP-20 removed the week controls it implies. Needs the form to learn which presets the season supports. Owner 2026-08-06: also in scope — the pre-start settings editor's identical dead-preset refusal; its Season range select filters the same way, computed against the league's own bound season (which may not be the latest). Ref: ADR-0020; spec §Game Mode 1 League Settings. _(deps: SIMP-20)_
- [x] **LG-10** — Commissioner surfaces disable themselves once their window has closed, with an inline reason, instead of rendering enabled and failing on save. `canActOnLeague` (`apps/web/src/lib/league.ts`) hardcodes `preStart: true`, so every control renders optimistically and the server's 409 is the only feedback — a commissioner edits locked settings and is told "Visibility and settings are locked once the league starts" only after pressing Save. `useAppNow()` plus the wire's `startsAt` makes the window computable from the **server's** clock, so this no longer needs the client to compute "now" (arch D11; engineering rules §Time), which is the reason the hardcode was written. The server's refusal stays the enforcement; the disable is a hint plus an explanation. Ref: spec §Commissioner Powers. _(deps: LG-6)_
- [x] **LG-11** — The dashboard's "New season available" pill reads by role. Every member sees it (`routes/_authed/index.tsx`), but only a commissioner can act on it, so a member watching it sit there for a fortnight has no way to learn it is waiting on someone else — the commissioner should see the opportunity, everyone else should see whose it is. No control moves: the renew action stays on the league overview, where the dashboard card already points (ADR-0009). Owner 2026-08-06: also in scope — the league overview gets a member-facing counterpart to the commissioner's renew banner, stating the same fact without the action, so the page the dashboard pill sends a member to corroborates it instead of sitting silent. Ref: spec §Commissioner Powers. _(deps: LG-7)_
- [x] **LG-12** — Conclude a league season. `LEAGUE_STATUS.CONCLUDED` is read by both pick services to refuse picks on a finished season and is written by **nothing**, and `renewLeagueSeason` only marks the new instance active — so the refusal is unreachable in every mode, every league season ever created stays `active` and is recomputed by `settle-sweep` every night forever (Survivor's replay is whole-season, so that cost grows with seasons × weeks), and the survivor board has to re-derive whether its season is over because nothing stores the answer. Decide who writes it and when — settlement reaching the last in-range week is the natural home, renewal closing the prior instance is the other half, and a league that is never renewed still has to conclude — and record the choice; the board then reads the status instead of restating settlement's completeness rule, which is the duplicated rule ELM-4 shipped with a comment rather than a fix. Ref: spec §End of League; arch D10; ADR-0025. _(deps: none)_
- [x] **LG-13** — Invite creation is pre-start only (owner, 2026-08-08). Joining is already refused once the cutoff passes (`join_closed`, derived from `leagueStartAt`), so this is not a hole — but a commissioner can still mint an invite link mid-season that nobody can use, which reads as a product that lost the invite rather than one that closed the door. **Not a flag flip:** `MANAGE_INVITES` is one action covering create, list *and* revoke, and revoking must stay available after the season starts so a leaked link can be killed. Split the capability rather than making the existing one `preStartOnly`. Applies to every mode. Ref: spec §Invites, §Membership. _(deps: none)_
- [x] **LG-14** — The Settings tab reads by role (owner, 2026-08-24): a member gets the league's settings stated as read-only values rather than the commissioner's form with every control disabled — greyed radios and steppers read as broken, not read-only, and the commissioner-only sections (Dues, Danger Zone) fall away with the form. Dues visibility and Leave league already reach members on the Members tab, so nothing moves there. Ref: spec §Commissioner Powers; `docs/design-system.md`. _(deps: LG-6, DUES-3)_
